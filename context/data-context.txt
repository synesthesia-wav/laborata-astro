Ground-Up Redesign Proposal: From Curated Catalog to Living Evidence Graph
1. Core Insight
The current system treats labri.catalog.json as a static, curated source of truth, then patches it with overlays (curated-tests.json, curated-mappings.json) to correct overmerges and missing items. This creates a brittle, hard-to-audit pipeline where every fix is a new veto layer.

The ground-up solution should invert this:

The canonical set is not an input but an output of a continuous synthesis from raw vendor data, with human review only for ambiguous cases.

The canonical identity is based on a content-defined tuple (analyte, fraction, specimen, immunoglobulin, maybe method) with an explicit provenance trail (imported from vendor X, minted by LLM on date Y, split from MKT_Z, etc.).

The entire pipeline is event-sourced: every change to the canonical set or mappings is recorded as an immutable event, enabling replay, audit, and rollback.

This eliminates the need for overlays and vetoes: the canonical set is rebuilt (or incrementally updated) each cycle from evidence, not patched post-hoc.
